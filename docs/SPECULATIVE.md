# Speculative Multi-Frame Decoding: Draft Model, Corpus, and Training

Technical report, part 1 (method and corpus; measurements follow as
they are produced). Hardware: NVIDIA DGX Spark (GB10, `sm_121`).
Companion to [SERVING.md](SERVING.md) §10–11, which establish why this
track exists.

## 1. Motivation, from measurements

Two measured walls point at the same lever. Single-stream, the engine
reads all ~4.37 GB of INT4 weights once per 46.4 ms frame — RTF 0.58 is
that memory stream, and no further weight-precision step survives the
quality gate ([QUANT.md](QUANT.md)). Concurrently, the per-stream cost
is the O(M) arithmetic of the batch GEMV: every bit-identical
reorganization lost to the plain kernel, and the tensor-core path wins
only from batch 16 ([SERVING.md](SERVING.md) §10–11).

Speculative decoding attacks both at once: a cheap draft proposes k
future frames, and the backbone verifies all k in ONE pass. Decode is
bandwidth-bound, so a k-row verify pass streams the same weight bytes
as a 1-row step — every accepted draft frame is close to free. Fewer
backbone passes per second of audio helps the single stream; the verify
pass itself widens the effective batch (sessions × (k+1) rows), which
is exactly the regime the tensor-core GEMM of §11 was kept for.

## 2. Why the draft must carry the fast-AR chain

S2-Pro is dual-AR: per frame, the backbone's final-normed hidden h_t
yields the semantic token (sampled), and the 4-layer fast-AR — greedy,
conditioned on h_t — emits the nine residual codebooks. The input
embedding of frame t+1 is a function of frame t's FULL code set (token
embedding plus all ten codebook embeddings, scaled 1/√11).

A draft that only proposes semantic tokens therefore cannot chain: to
build the verify input for position t+2 it must also produce frame
t+1's codes, which requires a hidden good enough that the greedy
fast-AR run on it reproduces the codes the true hidden would give.
Acceptance of a drafted frame is thus a conjunction: the semantic token
survives the accept/reject rule AND the nine greedy codebook argmaxes
match. The second condition is the one no speculation paper measures
for us, so the trainer reports it directly (§5).

## 3. Draft architecture

EAGLE-style, chosen so native inference reuses the engine's slow-AR
layer kernels unchanged:

- **fuse**: Linear(5120 → 2560, no bias) over [h_t ; e_{t+1}], where
  e_{t+1} is the backbone's own (frozen) input embedding of frame t;
  initialized as identity on the hidden half.
- **one backbone-shaped block**: GQA 32/8, head_dim 128, qk-norm,
  SwiGLU FFN 9728 — initialized from backbone layer 35 (~0.1 B
  parameters, ~1/36 of a backbone pass).
- **final RMS norm** (initialized from the backbone's) predicting the
  next final-normed hidden directly; the FROZEN tied-head slice scores
  it, so the draft never learns its own vocabulary head.

## 4. Corpus: 1,300 texts from a 31-agent generation workflow

The first corpus draft reused the 22 QAT texts and was rejected on
review: with content repeating after 22 texts, a take-level holdout
still shares every text with training — the eval would have measured
memorization. The rebuilt corpus:

- **1,300 texts** generated by a 31-agent Claude Sonnet workflow in one
  pass: 1,000 short texts over the seven deployment languages (DE 250,
  EN 201, FR 129, ES 129, RU 100, UK 99, TR 89) in ten rotating styles
  (announcements, explainers, mini-stories, dialogue forms, news,
  instructions, number/date/time-heavy, emotional/exclamatory,
  quiz, first-person smalltalk), ~250 code-switching texts mixing at
  least three of the seven languages mid-text (about a third touching
  all seven — language switches inside a take are the hard case for a
  hidden-state predictor), and 50 long texts (150–250 words).
  Deduplicated, bracket-free (square brackets are engine prosody
  control), each ≥ 60 characters.
- **82 texts held out by TEXT**, never generated for training. The
  trainer's `--eval-dump` evaluates only on takes from these, so the
  reported acceptance metrics measure generalization to unseen content.
- **Generation grid**: every training text × 2 seeds (long × 3), voice
  deterministic per (text, seed) over the full 33-voice registry;
  sequential requests at batch 1 so the EOS sentinel in the dump cuts
  exact per-take sequences. Target: ~2,500 takes, roughly 25 h of
  audio, ~2 M (hidden, frame) transitions — generated overnight by the
  serving engine itself at RTF ≈ 0.58.

Each dump record is [2560 bf16 final-normed hidden][i32 semantic]
[10 × i32 codes] (5,164 B per frame); the corpus is on-policy by
construction — the draft trains on exactly the distribution the engine
produces in deployment, sampling temperature included.

## 5. Training and the metrics that decide

The recipe follows an external literature review (EAGLE-1
arXiv:2401.15077 including its training code, EAGLE-3
arXiv:2503.01840, HASS arXiv:2408.15766, Leviathan arXiv:2211.17192,
and the NVIDIA NeMo drafter guide), adapted where our model differs:

- **Loss**: SmoothL1 on the predicted hidden + KL over the frozen
  head's 4,096 semantic rows. EAGLE's published 0.1 classification
  weight is a magnitude normalizer for a 32k vocabulary, not a law;
  both terms are logged separately and the weight is set so they land
  within ~2× of each other (start 0.3 over our 4,096-row slice).
- **Optimizer**: AdamW β = (0.9, 0.95), weight decay **0** — several
  draft parameters are RMSNorm gains initialized from the backbone,
  and decaying them toward zero corrupts a good init (a latent bug the
  review caught in the first trainer version). lr 1e-4, 5 % linear
  warmup, cosine to 0.1×, gradient clip 0.5.
- **Schedule**: 8,000 steps × batch 8 × sequence 1,024 frames
  (~8,200 frame-samples per step; ~6 epochs over the phase-1 corpus).
- **Feature noise**: uniform ±0.05 on the input hiddens. EAGLE's
  ±0.1 is relative to LLaMA's hidden scale and its own code scales it
  with sequence length; ours is set from the measured statistics of
  the final-normed hiddens (σ_global 0.52, mean per-dim σ 0.32 over
  114k frames), i.e. ≈ 0.1 σ, sweep planned 0.1–0.3 σ.

Evaluation every 1,000 steps, on held-out takes that are unseen BY
TEXT and additionally split by unseen VOICE (three whole registry
voices never appear in a training take), reports:

1. **hidden cosine** — the regression target itself;
2. **teacher-forced semantic argmax agreement** — the 0-depth
   acceptance proxy, an upper bound only;
3. **rollout α-curve (depth 1–4)** — the draft's own predicted hidden
   is fed back for k steps (tokens stay the true trajectory's, the
   EAGLE n-α definition), because teacher-forced numbers cannot see
   the feature-error compounding that dominates real acceptance at
   depth ≥ 2;
4. **fast-AR chain rate per depth** — all nine greedy codebook
   argmaxes from the predicted hidden must equal those from the true
   hidden. This is the acceptance condition specific to a dual-AR
   model; no published speculation work measures it.

Draft depth target k = 4 (expected accepted frames per verify pass =
(1−α^{k+1})/(1−α); below α ≈ 0.6 there is little return past k = 3).

**Known risk, stated up front**: token-exact speculative decoding on
audio tokens has a published failure — on LLaSA-8B a 5.2×-faster draft
delivered a net 0.98× because near-ties among acoustic tokens rejected
almost every proposal (arXiv:2511.13732); CosyVoice 2 needed relaxed
acceptance for its 1.4× (arXiv:2505.15380). Our position is more
favorable — the draft proposes 4,096-entry *semantic* tokens, exactly
the codebook class VADUSA (arXiv:2410.13839) found predictable — but
the honest sequence is: measure exact-acceptance α first; if the
rollout curve lands below ~0.45, the documented fallback is
similarity-group acceptance over the frozen head embeddings, not more
recipe tuning. A regression-free second run (EAGLE-3's ablation
attributes its data-scaling to dropping the feature loss) and
multi-step training-time unrolling (HASS) are the queued follow-ups.

Results are appended to this report as they are measured.
